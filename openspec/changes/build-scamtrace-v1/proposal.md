# Proposal

## Why

詐騙多半經過數天、數十則訊息，從聊天、建立信任逐步轉到要求匯款或提供資料；常見防詐工具多以查證單則訊息、網址、電話為主，較難看出整段對話在哪裡開始轉向。同時，把完整聊天紀錄上傳到第三方網站本身就有個資外洩風險。ScamTrace v1 要在不外流個資的前提下，分析整段對話的說服手法與轉折點。

## What Changes

- 新增帳號系統（訪客／user／admin），含密碼強度、登入鎖定、CSRF 與安全的 Session。
- 新增 LINE 匯出 .txt 與「貼上文字」兩種匯入方式，切出每則訊息的時間、發話者、內容與訊息類型。
- 新增本機去識別化：電話、帳號、身分證、卡號、Email、網址路徑、LINE ID、地址與發話者名字在分析前換成代號；原文與對照表不寫入資料庫、不送出本機。
- 新增「上傳 → 預覽（可手動補遮）→ 確認送出」的案例流程，及案例列表、刪除、示範案例。
- 新增話術分析：以語言模型依 Cialdini 七項原則＋威脅恐嚇標籤逐則標註手法、依據字句、階段，並判斷詐騙類型；模型不可用或輸出不合法時改用關鍵詞規則。
- 新增風險計分：每則風險、整體風險、風險等級與轉折點。
- 新增結果頁：摘要、SVG 風險時間軸、聊天泡泡與手法標籤標亮、手法統計，以及時間軸 JSON API。
- 新增使用者回饋（標註對錯與修正手法）。
- 新增管理後台：全站統計儀表板與操作日誌。
- 新增安全與稽核機制：參數化查詢、輸出跳脫、分析次數限制、操作日誌、統一錯誤頁。
- 新增自編示範資料與評估腳本，比較語言模型與規則比對的準確度。

## Capabilities

### New Capabilities
- `user-auth`: 註冊、登入登出、密碼規則、登入失敗鎖定、Session 安全、CSRF、角色權限。
- `chat-import`: 解析 LINE 匯出檔與貼上文字，產生訊息清單，並限制檔案大小、編碼與訊息數。
- `deidentification`: 偵測個資並換成一致代號、發話者匿名化、保留金額與網域、手動補遮。
- `case-management`: 預覽暫存與確認流程、原文丟棄、案例存取控制、案例列表與刪除、示範案例。
- `tactic-analysis`: 話術、階段、詐騙類型的分類體系；語言模型分析與輸出驗證；長對話切段；規則備援。
- `risk-scoring`: 每則風險分數、整體風險與等級、轉折點判定。
- `results-view`: 結果頁摘要、風險時間軸、對話區標籤標亮、手法統計、時間軸 API、共用版面與 165 提示。
- `feedback`: 使用者對逐則或整體判斷回饋對錯與修正手法，並計算正確率。
- `admin-console`: 管理員統計儀表板與操作日誌查詢。
- `security-audit`: 注入與 XSS 防護、上傳檢查、分析次數限制、操作日誌事件與內容限制、錯誤頁。
- `evaluation`: 自編示範資料規格、人工標註標準答案、模型與規則的評估指標與報告措辭。

### Modified Capabilities
（無；本專案為全新系統）

## Impact

- 新程式碼：專案目錄結構見 SPEC.md §14（app.py、auth.py、parser.py、deidentify.py、analyzer.py、risk.py、stats.py、evaluate.py、templates/、static/、tests/ 等）。
- 新相依：Flask 3.x、Anthropic Python SDK；資料庫 SQLite（`instance/scam.db`）。
- 外部服務：Anthropic API（模型 `claude-opus-5-5`），只接收遮罩後文字；未設定憑證時系統仍可用規則比對運作。
- 環境變數：`SECRET_KEY`、`ANTHROPIC_API_KEY`。
- 交付物：書審作品頁 1–2 頁（截圖、ER 圖、評估表）。
